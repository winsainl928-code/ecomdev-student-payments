# Мини-учёт оплат учебного центра

Тестовое задание Ecomdev: API учеников и оплат, список должников за выбранный месяц и веб-интерфейс для телефона. Выбран **вариант Б — веб-страница**; Telegram-бот не требуется и не реализован.

Проект работает локально: Node.js 24, встроенный HTTP-сервер, SQLite через `node:sqlite`, обычные HTML/CSS/JavaScript. Внешних npm-зависимостей, облачной БД и платёжного провайдера нет. Это учёт уже внесённых оплат, а не приём настоящих платежей.

## Запуск с нуля

1. Установите **Node.js 24 LTS** с [официального сайта Node.js](https://nodejs.org/en/download). npm входит в установку.
2. Скачайте или склонируйте репозиторий и откройте терминал в каталоге с `package.json`.
3. Чтобы сразу посмотреть приложение с вымышленными учениками и оплатами, выполните:

```sh
node --version
npm run preview
```

Откройте **http://127.0.0.1:3000**. Установка пакетов через `npm install` не нужна. Для остановки нажмите `Ctrl+C`.

Команда `preview` использует отдельную БД `data/preview.sqlite`. При первом запуске в пустую БД добавляются четыре вымышленных ученика и три оплаты за текущий месяц. Повторный запуск сохраняет ваши изменения и не дублирует записи. Если явно задан `DB_PATH`, демоверсия использует этот файл; примеры добавляются только в пустую БД.

Чтобы начать со своими записями, остановите демоверсию и выполните:

```sh
npm start
```

Обычный `npm start` использует `data/school.sqlite` (либо заданный `DB_PATH`), автоматически создаёт таблицы и ничего не добавляет. Новая база будет пустой; существующие записи сохраняются. Команда `npm run demo` отдельно добавляет вымышленные данные в эту же базу, только если в ней ещё нет учеников.

## Как пользоваться страницей

- Выберите месяц отчёта: появятся должники и суммы, которые им осталось доплатить.
- Ищите учеников и должников по имени, группе или телефону.
- Из карточки ученика можно перейти к внесению оплаты или посмотреть историю его платежей.
- Разделы «Должники», «Ученики» и «История оплат» находятся в отдельном меню. На главном экране видны общий долг, число учеников с долгом и без него; в таблице отдельно показаны стоимость месяца, внесённая сумма и остаток. Фильтр позволяет оставить тех, кто оплатил часть или ещё не платил.
- Кнопка «Внести оплату» открывает отдельное окно. Выберите ученика, укажите сумму и дату. Сумму можно вводить с пробелами, например `10 000`. После сохранения окно показывает подтверждение с суммой, учеником и датой; кнопка «Готово» возвращает к обновлённому списку. Из подтверждения можно сразу перейти к истории ученика.
- Если дата оплаты относится к другому месяцу, форма предупреждает об этом: платёж сохранится в месяце своей даты и не уменьшит долг выбранного месяца отчёта.
- Кнопка «Весь остаток» подставляет долг в сумму оплаты, если дата относится к месяцу отчёта. Перед сохранением форма показывает будущий остаток или переплату. Окна и разделы появляются плавно; системная настройка уменьшения движения отключает анимации. Уведомления появляются поверх страницы, не сдвигая список.

### Другой порт или файл БД

Сервер слушает только `127.0.0.1`. Переменные `PORT` и `DB_PATH` позволяют выбрать порт и отдельный файл БД.

PowerShell:

```powershell
$env:PORT = '3001'
$env:DB_PATH = './data/review.sqlite'
npm start
```

Bash:

```sh
PORT=3001 DB_PATH=./data/review.sqlite npm start
```

Открывайте адрес с выбранным портом. Относительный `DB_PATH` задаётся от текущего рабочего каталога.

## Проверка

```sh
npm test
```

Тесты проверяют API и расчёт задолженности на отдельной тестовой БД. Они не требуют работающего сервера или внешних сервисов. Проверяются дробные суммы, частичная и полная оплата, переплата, календарные границы, валидация и сохранение данных после перезапуска.

Для ручной проверки в браузере:

- Создайте ученика, укажите месячную оплату и внесите частичную оплату за выбранный месяц.
- Убедитесь, что он попал в должники с правильным остатком.
- Внесите оставшуюся сумму: ученик должен исчезнуть из списка должников этого месяца.
- Выберите соседний месяц: оплата из предыдущего месяца не должна уменьшать долг в нём.
- Проверьте изменение и удаление ученика, а также страницу на узком экране телефона.

## API

Все суммы передаются десятичными строками, например `"500000.00"`. JSON-запросы используют `Content-Type: application/json`. Успешные списки учеников и оплат — JSON-массивы; ошибки возвращаются в виде `{"error":"описание"}`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /students` | Список учеников |
| `POST /students` | Создать ученика: `name`, `phone`, `group`, `monthlyFee` |
| `GET /students/:id` | Получить ученика |
| `PATCH /students/:id` | Изменить переданные поля ученика |
| `PUT /students/:id` | Изменить переданные поля; для этого задания работает как частичное обновление |
| `DELETE /students/:id` | Удалить ученика и его оплаты; успешный ответ без тела, HTTP 204 |
| `POST /payments` | Внести оплату: `studentId`, `amount`, `date` |
| `GET /students/:id/payments` | Список оплат ученика |
| `GET /debtors?month=YYYY-MM` | Должники и общая задолженность за указанный месяц |

Ученик имеет поля `id`, `name`, `phone`, `group`, `monthlyFee`. Ответ о должниках содержит `month`, массив `debtors` и строку `totalDebt`. У каждого должника есть `studentId`, `name`, `phone`, `group`, `monthlyFee`, `paid`, `debt`.

Примеры для Bash / Git Bash:

```sh
curl -X POST http://127.0.0.1:3000/students \
  -H 'Content-Type: application/json' \
  -d '{"name":"Тестовый ученик","phone":"+998900000001","group":"A-1","monthlyFee":"500000.00"}'

curl -X POST http://127.0.0.1:3000/payments \
  -H 'Content-Type: application/json' \
  -d '{"studentId":1,"amount":"100000.00","date":"2026-10-05"}'

curl 'http://127.0.0.1:3000/debtors?month=2026-10'
```

Во втором запросе замените `studentId: 1` на ID, полученный при создании ученика. Даты и имена в примере вымышленные.

## Правила расчёта и допущения

- В БД деньги хранятся целыми сотыми долями. Для API и интерфейса они преобразуются в десятичные строки. Это исключает расчёт задолженности через двоичные дроби вроде `0.1 + 0.2`.
- Месячная сумма ученика неотрицательная, отдельная оплата строго больше нуля. Максимум одной суммы — `999999999.99`. ТЗ не задаёт валюту; для примера интерфейс подписан UZS (сум). Конвертации и смешения валют нет.
- Дата оплаты — действительная календарная дата `YYYY-MM-DD`, месяц отчёта — `YYYY-MM`. Время суток и часовой пояс к записи оплаты не применяются.
- Учитываются только оплаты с датой в выбранном месяце. Долг равен `max(месячная сумма − сумма оплат месяца, 0)`. Полная оплата и переплата исключают ученика из должников.
- Переплата не переносится на следующий месяц, долги предыдущих месяцев не суммируются. Это выбранное упрощение, поскольку в ТЗ нужен отчёт по одному месяцу.
- Текущая месячная сумма ученика применяется к любому выбранному месяцу. Истории тарифов и даты зачисления нет: изменение суммы изменит и расчёт прошлых месяцев. В варианте для реального центра это нужно заменить начислениями по месяцам.
- Удаление ученика удаляет связанные оплаты. Вариант для реальной бухгалтерии должен сохранять историю и использовать архивирование.

## Что улучшить за ещё одну неделю

1. Добавить вход, роли администратора и кассира, журнал изменений и архивирование вместо удаления истории.
2. Ввести начисления по месяцам и историю тарифов: зачисление в середине месяца, изменение цены и перенос переплат должны рассчитываться явно.
3. Сделать резервные копии БД и проверить восстановление на отдельном файле.
4. Добавить отдельный фильтр по группам, постраничную выдачу для больших списков и экспорт отчёта.
5. Добавить идемпотентность внесения оплаты и защиту от повторной отправки одного платежа.
